# DOMAIN 6 — Quoting & Proposals: Workflow Research

**Scope:** CPQ inside the sales room, product/price-book catalogues, multi-currency pricing, discount approval chains, quote & proposal generation with e-signature, order forms, contract lifecycle hooks, deal-desk approval routing.

**Method:** All workflows below are traced to vendor primary documentation that was read directly (Microsoft Learn, HubSpot Knowledge Base + Developer Docs, Oracle NetSuite Help, PandaDoc Developer Docs). Where a vendor blocks automated reading (Salesforce `developer.salesforce.com` returns HTTP 403; SAP `help.sap.com` pages are JS-rendered and return no readable body; Pipedrive `readme.io` and DocuSign `developers.docusign.com` return 429/empty) those are recorded as gaps, not invented.

**Vendors covered:** HubSpot (Revenue Hub CPQ), Microsoft Dynamics 365 Sales, Oracle NetSuite, PandaDoc (document/e-sign API).

## 1. Author a quote from a deal or opportunity

- **name:** Author a quote from a deal or opportunity
- **user_flow:**
  1. HubSpot: `CRM > Deals` → open a deal → in the right sidebar on the *Quotes* card click `+ Add` → choose **Create quote** → pick a quote template from the *Select a quote template* dropdown.
  2. HubSpot: in the quote editor, edit sections by clicking them in the quote preview or via the left sidebar **module editor** (opened via the site-tree icon); show/hide sections with the view/hide icons; drag modules to reorder; toggle **desktop/mobile** preview icons.
  3. HubSpot: in the *line items* module click **Edit all line items** → **Add line item** → either **Select from product library** (search by name/description/SKU, or **Advanced filters**; click **View tiers** for tiered products) or **Create custom line item** (optionally tick **Save line item to the product library**).
  4. HubSpot: set quantity, unit price, **Unit Discount** (`percentage` or `currency`), tax rate, billing start date, and optional/custom columns; click **Save**.
  5. HubSpot alternative entry points: **Breeze Assistant** ("generate a quote"), the *Revenue > Quotes* index page (**Create quote**), a deal/sales-workspace **board view** hover menu, or a deal-based **workflow** action **Create quote**.
  6. Dynamics 365 Sales: `Opportunities` → open opportunity → **Quotes** tab → **New Quote** (quote form prefilled with opportunity products) → adjust the **Products** area → fill **Shipping Information** and **Addresses** → **Save** → **Activate Quote** on the command bar.
  7. Dynamics 365 Sales alternative: site map → **Quotes** → **New** → set **Name**, **Price List**, **Currency** → set **Sales Information > Potential Customer** → Save → **Get Products** (from an opportunity) or **Add Product** → Save → **Activate Quote**.
- **data_flow:** Deal/Opportunity record (owner, currency, potential customer, address) → prefills the Quote header; the deal's line items are cloned into quote-specific line item records with *their own record IDs* → line item editor applies quantity, tier lookup, unit discount, tax → totals (Subtotal, discount, tax, Total, Future payments, Total contract value) recomputed on the quote → on publish, only the TCV is copied back to the deal amount and the quote's line items replace the deal's line items (deal and quote line items get different record IDs). In Dynamics, `Opportunity` + `OpportunityProduct` rows are read to produce `Quote` + `QuoteDetail` rows, each priced from a `PriceList`/`PriceListItem` against `Product`.
- **data_sources:** HubSpot CRM objects: deal (`0-3`), contact, company, product library, line item (`67` association), quote object; HubSpot Files tool (images/logos). Dynamics Dataverse tables: `opportunity`, `opportunityproduct`, `product`, `pricelevel`, `pricelevelproduct`, `quotedetail`, `account`/`contact`, `customeraddress`.
- **apis_hit:**
  - HubSpot CRM API v3/v2026-09: `POST /crm/objects/{version}/quotes` (create) with `hs_title`, `hs_expiration_date`, `hs_template_type=CPQ_QUOTE`; `POST /crm/objects/{version}/quote/{quoteId}/associations/default/{toObjectType}/{toObjectId}`; `GET /crm/objects/{version}/quote_templates?properties=hs_type`; `POST /crm/objects/{version}/quote_templates/search`; `GET crm/properties/{version}/quotes`.
  - Dynamics Web API / SDK for .NET: `POST /quotes` (Create), `GET /quotes`, `PATCH /quotes({quoteid})`; **`GenerateQuoteFromOpportunity`** action (`GenerateQuoteFromOpportunityRequest`), **`GetQuoteProductsFromOpportunity`** action, `GetQuantityDecimal` function, `CalculatePrice` event.
- **automations:** HubSpot deal-based **workflow** action "Create quote" (only available in deal-based workflows; the generic *Create record* action cannot be used for quotes). Breeze Assistant generation on demand. Pricing recalculates automatically whenever a line item quantity changes (tier boundaries re-evaluate) and on quote open/edit while in Draft.
- **features_tools:** HubSpot quote editor (module editor, site tree, desktop/mobile preview, AI icon per module), line item editor with editable columns, Breeze Assistant, workflow action library. Dynamics: Quote form (Products grid, Summary tab), **Get Products**, **Add Product**, **Activate Quote**, enhanced add-products experience, product bundles and **Suggestions** pane for upsell/cross-sell.
- **extensibility:** HubSpot — API-created quotes can attach any quote template; templates are created in UI; **custom-coded modules** can be built in the HubSpot CMS developer project but "isn't possible to create or add custom coded modules to a quote using the API"; Dynamics — plug-ins registered on quote messages, and `POST /quotes` + custom plugins; the Products/PriceListItem schema is fully customisable in Dataverse.
- **sources:**
  - https://knowledge.hubspot.com/quotes/create-and-send-quotes
  - https://knowledge.hubspot.com/cpq/understand-hubspot-cpq
  - https://developers.hubspot.com/docs/api-reference/latest/crm/objects/quotes/guide
  - https://knowledge.hubspot.com/quotes/create-custom-modules-to-use-on-quote-templates
  - https://learn.microsoft.com/en-us/dynamics365/sales/create-edit-quote-sales
  - https://learn.microsoft.com/en-us/dynamics365/sales/add-product-quote-order-invoice
  - https://learn.microsoft.com/en-us/dynamics365/developer/reference/entities/quote
  - https://learn.microsoft.com/en-us/dynamics365/sales/developer/quote-order-invoice-entities
- **evidence:** "In the right sidebar, on the *Quotes* card, click **+ Add**" … "Create quotes from deal records, the quotes index page, Breeze Assistant, or workflow actions. The owner of the deal will also become the owner of the quote." · "Line items are inherited from the associated deal, but line items on quotes have their own record IDs, separate to the deal line item record IDs." · "This action is only available in deal-based workflows. The Create record action can't be used for quotes." · Dynamics: "The quote form is prefilled with details from the opportunity record, including products added to the opportunity." · `GenerateQuoteFromOpportunity` "Event: True — **GenerateQuoteFromOpportunity action**".

## 2. Curate a product and price-book catalogue with tiered pricing

- **name:** Curate a product and price-book catalogue with tiered pricing
- **user_flow:**
  1. HubSpot: `CRM > Products` → **Create product** → in *Product information* enter **Name**, **SKU**, **Product description**, **Tax category**, **Product type**; upload/browse an **image** (Upload, or **Browse images** from the Files tool); under *Billing details* set **Billing frequency**.
  2. HubSpot: under *Pricing configuration* — for flat rate, enter **price** in each account currency field (via **Manage currencies**); for tiered pricing click the **Tiered pricing** tab → **Pricing method** (`volume-based` | `graduated` | `stair-step`) → **Unit cost** → per tier enter **minimum units** (maximum auto-computes; `∞` = open-ended final tier) → **+ Add tier** / delete icon.
  3. HubSpot: toggle **Active** off to retire a product from deals/quotes/subscriptions without deleting it. **Import** to bulk-import flat-rate products (tier-priced products can't be imported).
  4. HubSpot: `CRM > Products` → **Manage price books** → **Create price book** → name, description, **Currencies** dropdown (one currency per price book) → **Create** → **Add products** → edit **Price**, **Billing frequency**, **Term** per row → toggle **Inactive** off to activate.
  5. HubSpot: on a deal, `Line items` card → `+ Add` → the assigned price book shows at the top → add line items from it.
  6. Dynamics 365 Sales: `Products` with a price list → add product and **Price List Items** with a pricing method (Amount, Percent list price, Margin/Markup current or standard cost) and a **discount list**; price list is then selected on the quote/order/invoice.
  7. PandaDoc: manage the product catalog (`regular` and `bundle` item types; `billing_type` = `one_time` | `recurring`; `pricing_method`; `tiers[]` of `{min_qty, value}`; `cost`; `currency`; images; custom fields).
- **data_flow:** Admin-authored product records (name, SKU, description, tax category, billing frequency, image) + pricing configuration (flat price per currency, or tier table with min/max units and per-tier unit price) → stored in the product library → referenced by price books (HubSpot) or price list items (Dynamics) / catalog items (PandaDoc) → at quote-line creation the tier table is evaluated against quantity to select the effective unit price; the price-book/price-list layer then overrides the product's default price for the specific buyer segment or region.
- **data_sources:** HubSpot product object, HubSpot price books, HubSpot Files tool (images), HubSpot account currencies. Dynamics `product`, `pricelevel` (price list), `pricelevelproduct` (price list item), `discountlist`/`discountlistitem`, `uomschedule`, product bundle + bundle item, `territory`. PandaDoc product catalog (`/public/v2/product-catalog/items`), workspaces, content library.
- **apis_hit:**
  - HubSpot CRM Objects **Products API** — `developers.hubspot.com/docs/api-reference/latest/crm/objects/products/guide` (linked from the KB article as the developer resource).
  - PandaDoc: `GET /public/v2/product-catalog/items/search` (query params `query`, `types`, `billing_types`, `category_id`, `order_by`, `exclude_uuids`, `page`, `per_page`); `POST /public/v1/product-catalog/items` (create), GET/PUT/DELETE by uuid (per the API index at `developers.pandadoc.com/llms.txt`).
  - Dynamics: `pricelevel` and `pricelevelproduct` Dataverse tables; price resolution on the quote is driven by the `CalculatePrice` message/event.
- **automations:** Pricing recalculates on quote open/create/update and on product add/update/delete while `Use system pricing calculation = Yes` (`Organization.OOBPriceCalculationEnabled`). Volume discount recalculates whenever quantity changes "even when the parent entities are locked". Price book **auto-assignment** assigns a book at deal creation (see workflow 3).
- **features_tools:** HubSpot product builder, **Manage price books** index, **View tiers** column action, product index page with **Edit columns**, bulk **Import**/**Export**, **Restore records** recycle bin (90 days). Dynamics: Product form, price list form, price list item form, discount lists, product bundles, product families, **Suggestions** pane.
- **extensibility:** HubSpot — custom properties created on the product object are also added to the line item object; `Products API`; tier boundaries are authored in UI. Dynamics — plug-ins on the `CalculatePrice` message; full customisation of product/price list entities. PandaDoc — catalog item `custom_fields`, categories, `data_merge` custom column names, and bundles (`type: "bundle"`, `bundle_items_count`).
- **sources:**
  - https://knowledge.hubspot.com/products/create-and-manage-products
  - https://knowledge.hubspot.com/products/use-price-books
  - https://knowledge.hubspot.com/cpq/understand-hubspot-cpq
  - https://learn.microsoft.com/en-us/dynamics365/sales/price-calculation-opportunity-quote-order-invoice-records
  - https://learn.microsoft.com/en-us/dynamics365/sales/add-product-quote-order-invoice
  - https://developers.pandadoc.com/reference/search-catalog-items
- **evidence:** "Use tiered pricing to charge different rates for different quantities… **Volume-based** … the entire line item is priced based on the total quantity bought" / "**Graduated** … units are priced per tier" / "**Stair-step** … one flat fee is charged based on the quantity range." · "**∞** is the maximum value and creates an open-ended final tier." · "Tier priced products can't be imported." · "Create a referral price book with discounted pricing for referred buyers… Create regional price books to manage different pricing across countries or territories." · Dynamics: pricing-method table with formulas, e.g. "Margin current cost … Calculated price = current cost + [(current cost x percentage)/(100% - percentage)]". · PandaDoc catalog item JSON includes `"tiers": [{"value": 30, "min_qty": 1}, {"value": 20, "min_qty": 21}]`, `"pricing_method": 1`, `"billing_type": "recurring"`, `"type": "regular" | "bundle"`.

## 3. Auto-assign the correct price book or price list to a deal by rule

- **name:** Auto-assign the correct price book or price list to a deal by rule
- **user_flow:**
  1. HubSpot: `CRM > Products` → **Manage price books** → open a price book → hover **Assignment rules** → click the **edit icon**.
  2. HubSpot: in **Filters** click **+ Add filter** → configure deal-property filters (`and` / `or` groups) → review the matching deals in the right panel → toggle **Auto-assigned** on → **Save** → toggle the price book's **Inactive** switch off to activate.
  3. HubSpot: three modes are chosen deliberately — *No assignment rules* (manual only), *Assignment rules without auto-assignment* (test first), *Assignment rules with auto-assignment*.
  4. HubSpot override: on the deal's *Line items* card click **Price book: None** (or the price book name) → **Price book** dropdown → **Change price book**. Changing the price book removes previously added line items.
  5. Dynamics 365 Sales: enable the Sales tab system setting (or set `Organization.UseInbuiltRuleForDefaultPriceSelectionRule = 1`), associate a price level with a **Territory** using the **Territory Default Pricelist** connection role, and assign the territory to the user. Single match → price level set automatically; multiple matches → the user must choose.
- **data_flow:** Deal/company property values (HubSpot) or the acting user's sales territory (Dynamics) → filter/condition evaluation → one matching price book / price level is written onto the deal/quote header (`pricelevelid` in Dynamics) at creation → the product lookup and line-item price resolution are then scoped to that book, so only that book's products/prices/terms are browsable when adding line items → the quote inherits the price book from the deal.
- **data_sources:** HubSpot deal properties, company properties, price book object. Dynamics `territory`, `pricelevel`, `systemuser`, `organization.UseInbuiltRuleForDefaultPriceSelectionRule`.
- **apis_hit:** HubSpot — properties API (`GET /crm/properties/...`), deal object `PATCH` for the price book association. Dynamics — **`GetDefaultPriceLevelRequest`** message ("Dynamics 365 internally uses the `GetDefaultPriceLevelRequest` message to determine the default price level"), registrable as a plug-in: "Register the plug-in on the `GetDefaultPriceLevel` message."
- **automations:** Auto-assignment runs when a deal row is created ("Price books are auto-assigned only when a deal is created. After a price book is auto-assigned, HubSpot won't run auto-assignment again if the deal or associated company properties used in the filter are updated"). Dynamics `GetDefaultPriceLevel` fires on create/update of opportunity/quote/order/invoice rows.
- **features_tools:** HubSpot price book assignment-rule editor, deal *Line items* card price-book selector, Super Admin override. Dynamics System Settings → Sales tab, territory form + **Territory Default Pricelist** connection role, plug-in registration on `GetDefaultPriceLevel`.
- **extensibility:** HubSpot — "if multiple price books match, the deal owner can choose which matching price book to use"; Super Admins can override; turning **off** the *Create custom line items* permission forces price-book-only behaviour. Dynamics — replace the built-in rule with a plug-in that returns your own price level.
- **sources:**
  - https://knowledge.hubspot.com/products/use-price-books
  - https://learn.microsoft.com/en-us/dynamics365/sales/developer/set-default-price-level-for-opportunity-quote-order-invoice
  - https://learn.microsoft.com/en-us/dynamics365/sales/create-edit-quote-sales
- **evidence:** "When a deal matches exactly one assignment rule, that price book is automatically assigned." · "If multiple price books match, the deal owner can choose which matching price book to use." · "Quotes inherit the price book from the associated deal. Users can't select a price book when creating a quote; they must select it on the deal." · "If the price book is changed, any line items associated with the previous price book will be removed." · Dynamics: "If a single price level is returned, the price level is automatically set … If multiple price levels are returned, the price level field isn't populated and the user must specify a price level."

## 4. Quote in a transaction currency with FX conversion and same-currency constraints

- **name:** Quote in a transaction currency with FX conversion
- **user_flow:**
  1. Dynamics 365 Sales: create/edit the quote (or opportunity) → set the **Currency** lookup (a `transactioncurrency` record) and the **Price List**; the price list's currency must match.
  2. Dynamics 365 Sales: add products — the product lookup is filtered by the selected price list, and adding a product whose price list currency differs raises a pricing error.
  3. Dynamics 365 Sales: view totals — each money column is stored twice: transaction currency and `_Base` (organization base currency), with the read-only `ExchangeRate` column driving conversion.
  4. HubSpot: set the deal's **Currency** property; the quote's **Currency** label and formatting follow the deal. Account currencies are configured in Settings → **Manage currencies** and entered per-product and per-price-book.
  5. HubSpot: the quote editor's header module shows the currency; the *Totals* tab configures how discount is displayed (amount / percentage / both) in "the quote currency".
- **data_flow:** A `transactioncurrency` record (`ISOCurrencyCode`, `CurrencySymbol`, `CurrencyPrecision`, `ExchangeRate`) is chosen on the quote header (`transactioncurrencyid`) → line-item unit prices resolve from the `pricelevelproduct` row in that currency → totals (`totalamount`, `totallineitemamount`, `totaldiscountamount`, `totaltax`, `freightamount`) are computed in the transaction currency → the read-only `exchangerate` and `*_Base` columns (e.g. `totalamount_base`, `discountamount_base`) hold the converted base-currency view for reporting → on a wrong-currency combination, the platform refuses to price and sets `pricingerrorcode` (e.g. `34 Invalid Price Level Currency`, `38 Transaction currency is not set for the product price list item`).
- **data_sources:** Dataverse `transactioncurrency` table; `organization.basecurrencyid`; `pricelevel`, `pricelevelproduct`; quote/order/invoice `transactioncurrencyid` + `exchangerate` + `*_Base` columns. HubSpot deal/quote `Currency` property, account currency list, price book `Currencies` selection.
- **apis_hit:** Dynamics Web API: `GET /transactioncurrencies`, `POST /transactioncurrencies`, `PATCH /transactioncurrencies({transactioncurrencyid})`; the `RetrieveExchangeRate` message/event on the Currency table (`RetrieveExchangeRateRequest`, "Event: True"). `GET /transactioncurrencies(*transactioncurrencyid*)` for a single rate. HubSpot — `GET crm/properties/{version}/quotes` exposes `hs_currency`; `hs_currency` is a state-driven property populated on publish.
- **automations:** Currency/exchange-rate-driven recalculation on record open, create, update, and on product add/update/delete. HubSpot "quotes inherit the deal currency"; the quote's currency format is inherited from the deal record and "Changing the quote's locale settings won't update the currency."
- **features_tools:** Quote/order/invoice **Currency** and **Price List** fields; HubSpot quote **Header** module currency label; Totals tab **Total discount → Format** selector; **Manage currencies** settings page.
- **extensibility:** HubSpot — price books are single-currency ("Click the **Currencies** dropdown menu and select a currency"), so multi-currency is modelled as multiple price books; per-product price can be entered "in each of the currency fields". Dynamics — custom currency records (`CurrencyType: Custom`), plug-ins on pricing, and `exchangerate` is writable so a custom rate can be stamped.
- **sources:**
  - https://learn.microsoft.com/en-us/dynamics365/developer/reference/entities/quote
  - https://learn.microsoft.com/en-us/power-apps/developer/data-platform/reference/entities/transactioncurrency
  - https://learn.microsoft.com/en-us/dynamics365/sales/create-edit-quote-sales
  - https://learn.microsoft.com/en-us/dynamics365/sales/price-calculation-opportunity-quote-order-invoice-records
  - https://knowledge.hubspot.com/products/use-price-books
  - https://knowledge.hubspot.com/quotes/create-and-send-quotes
  - https://developers.hubspot.com/docs/api-reference/latest/crm/objects/quotes/guide
- **evidence:** "Your base record and all its line items must use the same currency… You can't change the currency of the base record (in this case, an quote), unless you remove all the line items associated with the record." · "`ExchangeRate` — Shows the conversion rate of the record's currency. The exchange rate is used to convert all money fields in the record from the local currency to the system's default currency." · `PricingErrorCode` option 38: "Transaction currency is not set for the product price list item"; option 34: "Invalid Price Level Currency". · `TransactionCurrency` table description: "Currency in which a financial transaction is carried out." · HubSpot: "Quotes created from deals match the associated deal's *Currency* property."

## 5. Enforce configuration and discount guardrails with quote rules before publish

- **name:** Enforce configuration and discount guardrails with quote rules
- **user_flow:**
  1. HubSpot: `Settings` → `Data Management` → **Objects** → **Select an object: Quotes** → **Rules** tab.
  2. Either click a **suggested prompt** in *Create a quote rule* (Breeze Assistant asks clarifying questions and drafts the rule), or click **Start from scratch** and type a rule definition in the quote-rules DSL.
  3. Under *Outcome* choose **Rule outcome type** = **Show warning** or **Block publish** → enter **Message to quote creator** → **Save rule**.
  4. Manage tab: open a rule name to edit, toggle the rule's **Status** off to disable, or delete it.
  5. A seller building a quote then sees the inline warning box in the line-items module, and publishing is blocked until the violation is fixed.
- **data_flow:** Line items, quote properties, and related records (deal, company, contacts, contract, quote template, current user) are read at rule-evaluation time → a SQL-like expression evaluates to true/false against the `WHERE`/quantifier/aggregate constructs → a true evaluation is a violation → violation either renders a warning banner in the quote editor with the configured message, or hard-stops the **Share/Publish** action, so the quote cannot reach the buyer.
- **data_sources:** HubSpot quote object, line items, product catalog (`hs_product_id`, `hs_sku`, `hs_product_type`), deal, company, contacts, `current_user` properties. Rule definitions are stored as text in the quote rules configuration.
- **apis_hit:** Quote rules DSL reference at `developers.hubspot.com/docs/api-reference/latest/crm/objects/quotes/quote-rules-syntax`; property validation resolves against `GET /crm/properties/...` (the "properties API"). Quote object endpoints for the evaluated record: `GET/PATCH /crm/objects/{version}/quotes/{quoteId}`.
- **automations:** Rules evaluate continuously while the quote is edited (warnings appear during build) and gate the publish step. Rules can be toggled on/off per rule; changes are staged in a sandbox environment for testing.
- **features_tools:** Settings → Objects → Quotes → **Rules** tab; rule editor with **Rule definition** and **Outcome**; Breeze Assistant prompt flow; **Block publish** outcome; **Manage** tab with per-rule **Status** switch; warning box in the quote line-items module.
- **extensibility:** The DSL is the extension surface — custom properties on any scope (`[quote.my_custom_property]`, `[line_item.x]`, `[deal.x]`, `[company.x]`, `[recipient_contact.x]`, `[current_user.x]`) are addressable; rules can be authored by prompt or hand-written; multi-branch workflows can be layered on top of the approval workflow.
- **sources:**
  - https://knowledge.hubspot.com/quotes/configure-quote-rules
  - https://developers.hubspot.com/docs/api-reference/latest/crm/objects/quotes/quote-rules-syntax
  - https://knowledge.hubspot.com/cpq/understand-hubspot-cpq
- **evidence:** "Use rules to display warnings when users build quotes or prevent them from publishing quotes until rule requirements are met." · "**Rule outcome type** … **Show warning:** display a warning when the rule requirements aren't met. **Block publish:** prevent users from publishing quotes when the rule requirements aren't met." · DSL examples: `SOLD_TOGETHER FROM line_item WHERE [hs_product_id] IN ("A","B","C")`, `INCOMPATIBLE FROM line_item WHERE [platform] IN ("legacy","modern")`, `SUM([quantity]) FROM line_item WHERE [hs_sku] = "ENT-LICENSE" > 5`, `[quote.hs_quote_amount] > 100000`, `MIN([hs_discount_percentage]) FROM line_item >= 5`. · Limitation: "quote-level discount properties are not available in the DSL." · "Arithmetic inside aggregate functions (e.g., `SUM([quantity] * [price])`) is not supported."

## 6. Route a discounted quote for standard approval

- **name:** Route a discounted quote for standard approval
- **user_flow:**
  1. HubSpot (Super Admin): `Settings` → `Data Management` → **Objects** → **Quotes** → **Approvals** tab → toggle **Approvals** on → under **Standard approvals** click **Edit** next to *Quotes*.
  2. Under *And these conditions are met* click **+ Add filter** → **Filtering on** dropdown (quote, line item, deal, …) → **[Object] properties** → search and pick a property (e.g. quote amount, discount level, SKU) → configure the filter → **+ Add filter** for additional criteria.
  3. Under *Then do this* → **Approvers** dropdown → select the users who can approve. Under *Approver requirements* choose **All approvers required** or **At least one approver required**. Enter **With this approval note**. **Save** → toggle the **Quotes** switch on to activate.
  4. Seller: in the quote editor, hover **Request approval** → **View approval conditions** to see why approval is required → click **Request approval** → add **Notes to approver** → the quote moves to *Pending approval*.
  5. Approver: from the bell/email notification (**Go to quote**) or the quotes index page filtered to **Pending approval** → open the quote → **Approvals** icon in the right sidebar shows notes, approvers and activity → **Approve** (with an optional message) or **Request changes** (enter changes → **Reject**).
  6. On request-changes, the seller edits and re-submits; "if there's more than one approver, and one approver requests changes, every approver will need to approve the quote again when the quote is re-submitted."
- **data_flow:** Quote properties (amount, discount, line-item SKU/discount, related deal) are evaluated against configured property filters at publish → if a match exists, the quote's state moves `Draft → Pending approval`, approver identities are resolved from the configured user list, and an approval record + note + notification is created → approver decision writes `APPROVED` or `REJECTED` back to the quote and notifies the creator → only on approval can the quote be **Share**d (state `Shared`) and sent to the buyer.
- **data_sources:** HubSpot quote object, line items, deal; HubSpot user records (approvers, `Approve quotes` permission); quote approvals records; HubSpot notification/email delivery.
- **apis_hit:** Quote state is exposed on the object: `hs_status` (DRAFT / PENDING_APPROVAL / APPROVED / REJECTED / ACCEPTED …) via `GET`/`PATCH /crm/objects/{version}/quotes/{quoteId}`. `hs_locked` becomes `true` on publish and must be reset by moving `hs_status` back to `DRAFT`/`PENDING_APPROVAL`/`REJECTED` to edit. Quote reassignment/approval activity "may be available through APIs depending on how the event is configured and the permissions of the API request."
- **automations:** Approval enrolment and notification fire on the publish/share attempt; approval activity is written to the quote activity log automatically (`Quote approval requested`, `Quote approval rejected / requested changes`, `Quote approved`). Approval notifications can be delivered to third-party apps (Google Chat, Microsoft Teams, Slack) via Settings → Notifications → **Other apps**.
- **features_tools:** Settings → Objects → Quotes → **Approvals** tab; **+ Add filter** property filter builder; **Request approval** button; **Approvals** sidebar panel; quotes index page **Status: Pending approval** view; bell/email notifications; **Copy approval link** action on a published quote.
- **extensibility:** Filters can target any object (quote, line item, deal) and any standard or custom property; up to 10 approvers; approval note is templated per rule; you can turn **off** the *Create custom line items* permission to force standard pricing; legacy quotes offer a simplified "all quotes approved by one user" mode.
- **sources:**
  - https://knowledge.hubspot.com/quotes/set-up-quote-approvals
  - https://knowledge.hubspot.com/quotes/manage-quote-approvals
  - https://knowledge.hubspot.com/quotes/create-and-send-quotes
  - https://knowledge.hubspot.com/quotes/manage-quotes
  - https://developers.hubspot.com/docs/api-reference/latest/crm/objects/quotes/guide

## 18. Revise a quote to create a new revision instead of losing the deal

- **name:** Revise a quote to create a new revision instead of losing the deal
- **user_flow:**
  1. Dynamics 365 Sales: open a quote that needs rework → on the command bar choose **Revise** (a quote is `Draft` with revision ID 0 when created; revision IDs increase by one each time).
  2. A **new quote** is created in `Draft` status and you start over on the new record; the original is closed with the `Revised` status reason (`quotecreationmethod` is stamped as `Revision`).
  3. On the new draft you can re-price, re-add products, adjust quantities/discounts, then **Activate Quote** again to issue the new version.
  4. Close alternatives: if you don't revise, the quote is closed as **Lost** or **Canceled** (a `quoteclose` activity is generated when a quote is closed).
  5. HubSpot analogue for re-issue: from the index page **Actions > Clone** the quote ("Cloned quotes include the original quote's record associations and the property values of the line items, including price, terms, and discount"), or **Recall & edit** a published quote before it is approved/accepted/paid and re-share it. Cloud Documents / project-style quote revisions (with activation and revision IDs) are documented for Dynamics 365 Project Operations.
- **data_flow:** Original `Quote` row in `Draft`/`Active` state + its `QuoteDetail` lines → `ReviseQuote` action creates a **new** `Quote` row with an incremented revision ID and `quotecreationmethod = Revision`, closes the prior row as `Revised`, and a `quoteclose` activity is written → the new draft is repriced (recalculating from the current price list, because draft prices are refreshed on open/edit) → activated and issued as the next version. Cloning a HubSpot quote deep-copies associations and line-item property values into new line item records.
- **data_sources:** Dataverse `quote` (state/status, `quotecreationmethod`, `closedon`, revision number), `quotedetail`, `quoteclose` activity, `pricelevel`/`pricelevelproduct`, product catalog. HubSpot quote object, line items, deal; quote activity log.
- **apis_hit:** Dynamics Web API / SDK: **`ReviseQuote`** (`ReviseQuoteRequest`, "Event: False"), **`CloseQuote`** (`CloseQuoteRequest`, Event: True), `WinQuote`, `RetrieveMultiple` on `quoteclose`. Quote entity properties `QuoteCreationMethod` (options: `776160000 Unknown`, `776160001 Revision`) and `ClosedOn` ("Enter the date when the quote was closed to indicate the expiration, revision, or cancellation date"). HubSpot — `POST /crm/objects/{version}/quotes/merge` for consolidation and `PATCH /crm/objects/{version}/quotes/{quoteId}` to set `hs_status` back to `DRAFT` for edits after publish.
- **automations:** Draft pricing is live: "In the draft state, the prices are adjusted to the actual prices on the price list when you open or edit the quote." Activated/closed quotes are frozen: "In the active and closed states, the prices aren't adjusted to the actual prices on the price list when you open or edit the quote." Revising writes the close activity automatically. HubSpot writes `Quote recalled` activity on recall and re-publish re-generates the link/PDF.
- **features_tools:** Dynamics quote command bar **Revise** / close options (Lost, Canceled, Revised), status-reason picker, revision-ID display. HubSpot **Actions > Clone**, **Recall & edit**, **Void**, **Archive**, **Delete**, and **Restore records** (published quotes with online payments or e-signature enabled can't be restored). Dynamics 365 Project Operations quote activation/revision concept for sales quotes.
- **extensibility:** Revisions are a first-class record lineage (`RevisionNumber`, `QuoteCreationMethod`, `ClosedOn`) so history is preserved; the original price list is re-read for the new draft, so repricing follows catalogue changes; HubSpot clone preserves line-item price/terms/discount values but creates fresh line item records; recall is blocked once approved, accepted or paid.

## 19. Generate a proposal from CRM data via a document API, gate it on internal approval, and sync status back

- **name:** Generate a proposal from CRM data via a document API, gate it on internal approval, sync status back
- **user_flow:**
  1. In your CRM, the deal/opportunity is won or a quote is created. Your integration builds the request body: `POST https://api.pandadoc.com/public/v1/documents` with `name`, `template_uuid`, `recipients[]` (email, first_name, last_name, `role`), plus `content_placeholders[]` (each with `block_id` and `content_library_items[]` containing `pricing_tables[]` with `options.currency`, `options.discount`, `sections[].rows[].data`/`options` and `custom_fields`), or a plain `pricing_tables[]` for a template with a pricing table.
  2. Response returns status `document.uploaded`; poll `GET /public/v1/documents/{id}/status` or wait for the `document_state_changed` webhook until it reaches `document.draft` (sending too early returns `409 Conflict`).
  3. Optionally update the quote section in place: `PUT /public/v1/documents/{id}/quotes/{quoteId}` with a `sections[]` payload (each section `id`, `items[]` with `sku`, `name`, `qty`, `price`, `cost`, `billing_frequency`, `contract_term`, `pricing_method`, `reference_type`, `reference_id`, `discounts`, `taxes`, `fees`, `total`). Omitting a section/item deletes it.
  4. If the template has an approval workflow, `POST /public/v1/documents/{id}/send` moves the document to `document.waiting_approval` instead of `document.sent`; select a specific approver via `selected_approvers.steps[].group.assignees[].is_selected`; after approval, call **send** again to move to `document.sent`.
  5. Deliver: leave `silent: false` for emailed notification, or `silent: true` and embed — `POST /public/v1/documents/{id}/session` with `{recipient, lifetime}` then the `pandadoc-signing` `Signing` library (`region: "com" | "eu"`), or share `shared_link` yourself. Optionally `POST /public/v1/documents/{id}/files` to attach a signed PDF and retrieve it via `GET /public/v1/documents/{id}/files/{attachment_id}`.
  6. Consume the `document_state_changed` webhook (`document.viewed` / `document.completed`, with `recipients[].has_completed`, `signature_date`, `fields[].assigned_to`, `grand_total`, `linked_objects[]`, `metadata`) and write back to the CRM: create/update a linked object (`POST /public/v1/documents/{id}/linked-objects`, provider + `entity_type` + `entity_id`), or use the Salesforce package's custom classes/triggers to subscribe to document events and sync status, products, notes/attachments and the opportunity stage.
- **data_flow:** CRM deal/quote record + product catalog → JSON body for `POST /public/v1/documents` → PandaDoc renders the template with merged tokens/fields, dynamic pricing tables (currency, discount, tax, fee) and content-library items chosen at creation time → the document moves through the state machine `uploaded → draft → waiting_approval → approved/rejected → sent → viewed → completed` (with `waiting_pay`/`paid` and `cancelled`/`declined` branches) → the `document_state_changed` webhook (HMAC-SHA256 signed) returns the full document payload → the integration writes status back to the CRM (opportunity stage/close date, notes & attachments including the signed PDF) and, via `linked_objects`, makes the document discoverable from the CRM record.
- **data_sources:** Your CRM (deals/opportunities, products, contacts); PandaDoc templates, content library items, product catalog; PandaDoc document/recipient/field/pricing objects; PandaDoc e-vault (completed PDF); CRM notes/attachments; webhook receiver endpoint.
- **apis_hit:** `POST /public/v1/documents`; `GET /public/v1/documents/{id}/status`; `GET /public/v1/documents/{id}/details`; `PATCH /public/v1/documents/{id}` (draft only); `PUT /public/v1/documents/{id}/quotes/{quoteId}` and `PUT /public/v1/documents/{id}/quotes/batch`; `POST /public/v1/documents/{id}/send`; `POST /public/v1/documents/{id}/session`; `GET /public/v1/documents/{id}/files/{attachment_id}`; `GET /public/v1/documents/{id}/download` / Download Protected Document; `GET /public/v2/product-catalog/items/search`; `POST /public/v1/documents/{id}/linked-objects`, `GET /public/v1/documents/linked-objects`, `GET /public/v1/documents/{id}/linked-objects`, `DELETE .../linked-objects/{id}`; `GET /public/v1/documents/{id}/audit-trail`; webhooks: `document_state_changed`, `document_updated`, `document_created`(failed), `quote_updated`, `recipient_completed`, `pdf_of_completed_document_available_for_download`, `template_*`, `content_library_item_*`; `POST /public/v1/webhook-subscriptions` with `X-PandaDoc-Webhook-Event-Id` de-dup header. Auth: `API-Key` header or OAuth2 (`read write` scopes, `/oauth2/authorize` + `/oauth2/access_token`).
- **automations:** Document creation is asynchronous (`document.uploaded` → `document.draft`); webhooks fire on every state transition without polling; `quote_updated` fires when a user saves in the Quote Builder; the internal approval workflow gates the send; retries are handled by de-duplicating on `X-PandaDoc-Webhook-Event-Id`; HMAC-SHA256 signature verification required; `shared_link` may be empty in webhook payloads (fall back to Document Details); the Salesforce package can "**automatically** generate documents after record creation or update without any user input."
- **features_tools:** Create-from-template, pricing tables (sections, multichoice, taxes, fees, `data_merge`), content placeholders, variables in titles, embedded editor / embedded sending / embedded signing, `pandadoc-signing` JS library, auto-reminder settings, signing order, identity verification (passcode/SMS/KBA/ID), notary requests, audit trail, webhooks console + history, and CRM packages (Salesforce custom classes/triggers, Dynamics custom JavaScript functions, Zapier flows).
- **extensibility:** Template + content library for reuse; `data_merge: true` maps your CRM column names into the pricing table; custom fields on catalog items and rows; `linked_objects` provides two-way CRM association; per-recipient `role`/`roles` (signer, cc, approver) and `signing_order`; `forwarding_settings` controls resharing; regions `com`/`eu`; multi-tenant workspace/folder structure; MCP server for LLM-driven document operations; and for Salesforce specifically, custom triggers to "Change default recipient or product information sent to PandaDoc from Salesforce", "Subscribe to PandaDoc document events and sync document data back to Salesforce", and "Subscribe to Salesforce record events and create PandaDoc documents."

# WF-102 - Revise a quote to create a new revision instead of losing the deal

- **Domain:** Pricing, quoting and proposals (`quoting-proposals`)
- **Research source:** `docs/research/raw/quoting-proposals.md` section 18
- **Distinct sources cited:** 5
- **Branch:** `feature/WF-102-revise-a-quote-to-create-a-new-revision`

## Research evidence

- **name:** Revise a quote to create a new revision instead of losing the deal
- **user_flow:**
  1. Dynamics 365 Sales: open a quote that needs rework → on the command bar choose **Revise** (a quote is `Draft` with revision ID 0 when created; revision IDs increase by one each time).
  2. A **new quote** is created in `Draft` status and you start over on the new record; the original is closed with the `Revised` status reason (`quotecreationmethod` is stamped as `Revision`).
  3. On the new draft you can re-price, re-add products, adjust quantities/discounts, then **Activate Quote** again to issue the new version.
  4. Close alternatives: if you don't revise, the quote is closed as **Lost** or **Canceled** (a `quoteclose` activity is generated when a quote is closed).
  5. HubSpot analogue for re-issue: from the index page **Actions > Clone** the quote ("Cloned quotes include the original quote's record associations and the property values of the line items, including price, terms, and discount"), or **Recall & edit** a published quote before it is approved/accepted/paid and re-share it. Cloud Documents / project-style quote revisions (with activation and revision IDs) are documented for Dynamics 365 Project Operations.
- **data_flow:** Original `Quote` row in `Draft`/`Active` state + its `QuoteDetail` lines → `ReviseQuote` action creates a **new** `Quote` row with an incremented revision ID and `quotecreationmethod = Revision`, closes the prior row as `Revised`, and a `quoteclose` activity is written → the new draft is repriced (recalculating from the current price list, because draft prices are refreshed on open/edit) → activated and issued as the next version. Cloning a HubSpot quote deep-copies associations and line-item property values into new line item records.
- **data_sources:** Dataverse `quote` (state/status, `quotecreationmethod`, `closedon`, revision number), `quotedetail`, `quoteclose` activity, `pricelevel`/`pricelevelproduct`, product catalog. HubSpot quote object, line items, deal; quote activity log.
- **apis_hit:** Dynamics Web API / SDK: **`ReviseQuote`** (`ReviseQuoteRequest`, "Event: False"), **`CloseQuote`** (`CloseQuoteRequest`, Event: True), `WinQuote`, `RetrieveMultiple` on `quoteclose`. Quote entity properties `QuoteCreationMethod` (options: `776160000 Unknown`, `776160001 Revision`) and `ClosedOn` ("Enter the date when the quote was closed to indicate the expiration, revision, or cancellation date"). HubSpot — `POST /crm/objects/{version}/quotes/merge` for consolidation and `PATCH /crm/objects/{version}/quotes/{quoteId}` to set `hs_status` back to `DRAFT` for edits after publish.
- **automations:** Draft pricing is live: "In the draft state, the prices are adjusted to the actual prices on the price list when you open or edit the quote." Activated/closed quotes are frozen: "In the active and closed states, the prices aren't adjusted to the actual prices on the price list when you open or edit the quote." Revising writes the close activity automatically. HubSpot writes `Quote recalled` activity on recall and re-publish re-generates the link/PDF.
- **features_tools:** Dynamics quote command bar **Revise** / close options (Lost, Canceled, Revised), status-reason picker, revision-ID display. HubSpot **Actions > Clone**, **Recall & edit**, **Void**, **Archive**, **Delete**, and **Restore records** (published quotes with online payments or e-signature enabled can't be restored). Dynamics 365 Project Operations quote activation/revision concept for sales quotes.
- **extensibility:** Revisions are a first-class record lineage (`RevisionNumber`, `QuoteCreationMethod`, `ClosedOn`) so history is preserved; the original price list is re-read for the new draft, so repricing follows catalogue changes; HubSpot clone preserves line-item price/terms/discount values but creates fresh line item records; recall is blocked once approved, accepted or paid.

If you revise it, a new quote is created, set to Draft status, and you can start over." · "`ReviseQuote` … Event: False … **ReviseQuote action**" · "`QuoteCreationMethod` … 776160001 **Revision**" · "In the draft state, the prices are adjusted to the actual prices on the price list when you open or edit the quote." · Project Operations: "A sales quote supports activation and revisions. A project quote doesn't support those processes."

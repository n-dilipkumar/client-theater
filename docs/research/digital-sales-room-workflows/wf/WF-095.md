## Research evidence

- **name:** Collect acceptance by e-signature, countersignature and identity verification
- **user_flow:**
  1. HubSpot (Super Admin): `Settings` → **Objects** → **Quotes** → **E-signature** tab → toggle **Identity verification** on → select a **Verification from email address** (team email; individual work addresses can't be used as the default) → also set the **E-signature from email address** (else `success@hubspot.com`).
  2. HubSpot: monitor quota under *E-signature usage this month* on the E-signature tab; limits are pooled per account by subscription and seat count and reset on the 1st.
  3. Seller: quote editor → **acceptance** module → in the sidebar select **E-signature** → tick the buyer contacts under **Buyer contacts required to sign** (or **+ Add contact**), optionally enable **Quote signer(s) can reassign**, and select **Countersigners** from your organisation. (Alternative acceptance methods: **Print and sign**, or **Accept without signature** with **Request acceptance from** = *Do not specify* / a specific contact / added contacts.)
  4. Buyer: opens the shared link → enters the quote password if one is set → optionally **Reassign this quote signer** and submit new signer details → if identity verification is on, clicks **Verify email** in the *Acceptance* section → receives "Please verify your identity to sign your quote" (one-hour window) → clicks **Verify your identity and sign quote** → **Start signing** → **Get started** → **Click to sign** → **Draw/Type/Upload** → **Insert** → **Continue** → **I agree** → **Close**.
  5. Countersigner: receives an email; from `Revenue > Quotes` with status *Pending signature* → hover quote → **Preview** → **Actions > Countersign** → complete the signing steps. Countersigners who start first do not need to verify.
  6. After all signatures: the customer receives a copy of the signed document (link expires with the quote) plus a PDF. The seller can **Download** the signed PDF from the index page.
  7. PandaDoc equivalent: `POST /public/v1/documents/{id}/send` (optionally `silent: true`) → `POST /public/v1/documents/{id}/session` with `{recipient, lifetime}` → embed with the `pandadoc-signing` `Signing` library (`region: "com" | "eu"`) or share a link; identity verification is enabled per-workspace (passcode, SMS, KBA, ID check).
- **data_flow:** Quote acceptance configuration (`hs_acceptance_method`, signer contacts, countersigners) + buyer email → on send, a signing envelope is created (HubSpot's e-sign is powered by **Dropbox Sign**) → the buyer's identity is verified via an emailed one-time link (HubSpot/Dropbox Sign) before the signature widget unlocks → the drawn/typed/uploaded signature is bound to the quote document and a signature field record is written → the quote's signing status advances (`Pending signature` → `Viewed - pending signature` → `Pending countersignature` → `Accepted`) and `hs_clickwrap_accepted_by` / payment status update → activities (`Quote buyer signed`, `Quote countersigned`, `Quote reassigned`, `Signing attempt failed`) are appended to the quote activity log; if *Automatically create contracts from accepted quotes* is on, a contract (and, in Connected CPQ, an order) is created.
- **data_sources:** HubSpot quote object, contact records (signers/countersigners), user records (countersigners), Dropbox Sign e-signature service, verification email delivery (`success@hubspot.com` or a configured team address), quote activity log. PandaDoc: document, recipients, signature fields, `DocumentFields`, e-vault for the completed PDF.
- **apis_hit:** HubSpot — `POST /crm/objects/{version}/quotes` with `hs_acceptance_method` = `clickwrap` | `esignature` | `print_and_sign`; `hs_esign_num_signers_required`; `hs_clickwrap_accepted_by`; `hs_payment_status`; contact association type `702` (signer). PandaDoc — `POST /public/v1/documents/{document_id}/send`; `POST /public/v1/documents/{document_id}/session`; `GET /public/v1/documents/{id}/status`; `GET /public/v1/documents/{id}/details`; `GET /public/v1/documents/{id}/download` (and Download Protected Document for completed, production-key-only); `PUT /public/v1/documents/{id}/fields/assign` to assign/reassign fields; `PUT .../recipients` to change signer; `POST .../documents/{id}/session` with `lifetime` for embedded sessions.
- **automations:** Enabling e-signature on a **published** quote consumes quota immediately: "An e-signature will count toward the limit as soon as the e-signature option is turned on for a published quote. The quote doesn't need to be signed to apply to the signature limit." Multi-signature quotes count as one: "if a published quote with e-signatures enabled requires three signatures, this only counts as one usage toward your limit." Resending after expiry/recall costs another. Countersigners are emailed automatically when the buyer signs. Contract/order creation fires on acceptance. Signing-attempt failures are logged automatically.
- **features_tools:** HubSpot **acceptance** module, **E-signature** tab settings (identity verification, from-addresses, usage), signing widget (Draw/Type/Upload), **Reassign this quote signer**, **Verify email** step, **Actions > Countersign** on the index page, **Download** signed PDF, notification settings. PandaDoc Embedded Signing library, `document.viewed`/`document.completed` events, Identity Verification, signing order configuration.
- **extensibility:** HubSpot — countersigners are drawn from your own users; custom countersigner/buyer sets per quote; reassignment is per-quote configurable; `hs_acceptance_method` is scriptable via API; quote attachments can be marked **In signing** to be included in the envelope. PandaDoc — regions (`com`/`eu`), `silent` delivery for embedded/alt-channel signing, `forwarding_settings.forwarding_allowed` / `forwarding_with_reassigning_allowed`, `signing_order` per recipient, `role`/`roles` (signer, cc, approver), shared links vs embedded sessions.

- **evidence:** "HubSpot's e-sign feature is powered by Dropbox Sign (formerly HelloSign)." · "Buyers have one hour to complete the signature process after clicking **Verify email**." · "if you download a signed quote, Dropbox Sign removes links from any hyperlinked text included in the *Cover letter*, *Executive summary*, or *Terms* sections from the PDF version." · "Attachments can be marked as *In signing* to be included in the signing envelope of an e-signature. If an attachment is marked *In signing*, e-signature must be used for the quote." · "Quote PDFs larger than 40 MB may not be successfully verified or signed." · PandaDoc: "It is your responsibility to verify the identity of any user who views a document within the signing session. Some use cases legally require Identity Verification to be enabled."

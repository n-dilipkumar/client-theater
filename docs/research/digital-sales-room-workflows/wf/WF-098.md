# WF-098 - Expire a quote and auto-send buyer reminders

- **Domain:** Pricing, quoting and proposals (`quoting-proposals`)
- **Research source:** `docs/research/raw/quoting-proposals.md` section 14
- **Distinct sources cited:** 5
- **Branch:** `feature/WF-098-expire-a-quote-and-auto-send-buyer-reminders`

## Research evidence

- **name:** Expire a quote and auto-send buyer reminders
- **user_flow:**
  1. HubSpot (Super Admin): `Settings` → `Objects` → **Quotes** → set **Set a default expiration period** between 1 and 365 days → **Update**. "Any new quotes created after the setting is turned on will automatically use the configured expiration date."
  2. HubSpot: `Settings` → `Objects` → **Quotes** → **Reminders** tab → under *Reminder schedule* set the number of days and choose **Days after sending quote** or **Days before expiration date** → **+ Add reminder** / delete icon to manage several → set *Reminder send time* (in the account time zone) → **Preview reminder email** → toggle **Send automated reminders to quote recipients**.
  3. Seller: quote editor → **header** module → under *Expiration date* click the **date picker** to set a specific date, edit the **Label**, or toggle the **Expiration date** switch off.
  4. HubSpot: because a past *Effective date* is allowed, "the **Expiration date** will be treated as the buyer's sign-by deadline."
  5. PandaDoc equivalent: `PUT /public/v1/documents/{id}/settings` / auto-reminder settings configure automatic reminders after initial dispatch (email/SMS channel, initial delay, frequency); `POST /public/v1/documents/{id}/reminders` sends a manual reminder; `GET .../auto-reminder/status` reports per-recipient reminder status. PandaDoc documents also carry an `expiration_date` in state-change payloads.
- **data_flow:** Quote send/publish timestamp + configured expiry window → the quote carries an expiration date (`hs_expiration_date`; `expireson` in Dynamics) → a scheduled job evaluates sent/published quotes relative to that date and dispatches reminder emails at the configured offsets → if the buyer has not accepted/e-signed/marked-signed by the expiration date, the quote transitions to an Expired state (logged as `Quote expired`) and the buyer loses the ability to accept; expired quotes can still be downloaded, cloned, voided or archived, and resending counts as a new send (consuming e-signature quota again).
- **data_sources:** HubSpot quote object (`hs_expiration_date`, status), HubSpot transactional email, account time zone setting, quote activity log. Dynamics quote `expireson` / `effectiveto` / `effectivefrom` fields. PandaDoc document `expiration_date`, auto-reminder settings, per-recipient reminder status.
- **apis_hit:** HubSpot — `hs_expiration_date` is a required property on `POST /crm/objects/{version}/quotes`; reminder schedule is configured in settings (no documented public write API on the pages read). PandaDoc — `PUT /public/v1/documents/{id}/auto-reminder-settings` (update) and `GET /public/v1/documents/{id}/auto-reminder-settings` (retrieve), `GET /public/v1/documents/{id}/auto-reminder/status`, `POST /public/v1/documents/{id}/reminders` (manual), per the API index; `expiration_date` appears in the `document_state_changed` webhook payload.
- **automations:** Scheduled reminder dispatch (time-relative to send and to expiry, in the account time zone). Expiry check is a background job: "If a buyer hasn't accepted or signed a quote by the expiration date, it'll expire." Expiry semantics depend on acceptance method — e-signature/click-to-accept/print-and-sign each have their own "won't expire if" rule, and a quote accepted or signed but not countersigned or paid still does not expire.
- **features_tools:** Quote settings **Reminders** tab, **Preview reminder email**, expiration date picker + label, status filters for "expiring soon", *Analyze your published quotes* expiration filter, `Actions > Recall & edit` (possible before approval/acceptance/payment), **Void** (deactivates the quote link URL), **Archive** (unpublishes and hides from the default index view but blocks buyer access).
- **extensibility:** Multiple independent reminder rules; either offset (post-send or pre-expiry); per-timezone send time; a past effective date repurposes expiry as a sign-by deadline; reminder + expiration events are exposed as quote activities that can drive workflows.

1. **Edit no shared file.** These are the files that stall every other branch:
- `backend/dsr/api.py`

   CI now *fails* any pull request that touches one of them
   (`.github/workflows/ci.yml`, the `guard` job). You do not need to open a PR,
   but run the guard yourself before you push:
       "C:/Users/Dilip/orca/projects/client-theater/client-theater/.venv/Scripts/python.exe" tools/check_feature_diff.py --base origin/main
   It must print `OK: ... none shared`.

2. **Never import from `dsr.api`.** Import from `dsr.deps` instead. That is what
   keeps a feature independently testable and keeps two features from needing to
   edit a file they share.

3. **All reads and writes go through `StoreDep` / `RecordStore`.** Never open the
   SQLite file. The audit row is written in the same transaction as the change,
   and that is the guarantee the whole product is built on.

4. **Pass `source=` from the HTTP layer.** If a domain function you are porting
   hardcodes a URL string as the `source` of a write, that is a defect, not a
   port detail. The audit row must name the route that actually served the write.
   This exact bug shipped once already: a feature's audit log kept recording a
   path the app had stopped serving. Add a `source` parameter and pass
   `f"POST {router.prefix}/..."` from the route.

5. **Payloads stay schema-flexible.** No migration, no typed column, no new
   required field. A team adding a field must not need coordination with anyone.

6. **Put demo data in `seed(db, context)` in your own feature module.** Do not
   edit `backend/seed.py`. A feature whose page is empty in the demo is a feature
   nobody can review, so seed something representative and return a short string
   describing what you added.
